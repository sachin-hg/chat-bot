## Resolved Answers (PM clarifications)

### OQ-001 — Session token design
- **BE generates a `token_id`** on first `GET /chat/get-conversation-id` call (UUID, not JWT)
- Stored as a cookie by FE, passed on every request as `token_id`
- Maps anonymous chats to a device
- `login-auth-token` is passed separately when user is logged in (created by Housing login service on FE; BE validates it by calling the login service API — BE does NOT create it)
- On `migrate-chat`: `token_id` is claimed by the logged-in `user_id` → chat associated to user
- On logout: FE deletes both cookies. Next `get-conversation-id` request → new `token_id` generated by BE
- **BE implementation:** simple UUID, no signing. Store mapping `token_id → conversation_id` in the `conversations` table.

### OQ-002 — contactSeller
- **BE never calls a CRM or lead-creation API** for `contact_seller`
- `execute_tier1_action` for `contact_seller` = emit `contact_seller` template from session state only (no API call)
- **FE handles the actual contact initiation** (shows phone/WhatsApp, calls its own vendor APIs)
- **FE also sends `contact_seller_confirmed`** (`responseRequired: true`) back to BE so the pipeline generates a follow-up suggestion ("want similar properties / locality reviews / floor plan?")
- **Venus is NOT removed from the BE** — Venus remains the primary data source for:
  - New-launch project details: gallery images, floor plans (`getFloorPlans`), brochure (`getBrochure`), amenities, highlights, sellers list, project overview (`getProjectDetail`)
  - A Casa listing's `region_entity` field links to the Venus project ID when the unit is inside a new development
- **Impact on CHAT-P-030**: remove only the CRM/lead-creation tool call; all Venus data-fetch tools remain. Add `contact_seller_confirmed` follow-up intent handling.

### OQ-003 — Anonymous users + portfolio
- `portfolio/recent_searches`: **works with `token_id`** — BE stores search history keyed by token_id, no login required
- All other portfolio intents (`saved_properties`, `viewed_properties`, `recommendations`): **hard login block** → `login` template
- **Impact on CHAT-A-008**: session must track `search_history` keyed by `token_id` (even for anonymous)

### OQ-004 — transaction_type inference
- **Message + conversation context only** — user's profile is NOT consulted
- SLM infers buy/rent from message signals ("under 80L" → buy, "2500/month" → rent)
- Session holds `transaction_type` once inferred; SLM can update it on a pivot
- No profile API call needed

### OQ-005 — experiments.yaml
- **Git-tracked** when the config contains no credentials (feature flags, prompt variants, flow variants)
- **Feature flag service** (e.g. LaunchDarkly, or simple env-var based toggle) when credentials or sensitive targeting are involved
- For MVP: all experiments in `config/experiments.yaml`, committed to repo. Secrets never in this file.
